# Отслеживание статуса заказа через Socket.IO

Статус обновляется в реальном времени на экране конкретного заказа. «Мои заказы» показывает последнее состояние, сохранённое в этом браузере. В production Socket.IO подключается через домен PWA. Контракт NestJS остаётся прежним.

## Подключение и подписка

- [x] Добавить `socket.io-client@^4.8.4` в `apps/web`.
- [x] Настроить прокси Vite для `/socket.io/` на NestJS с поддержкой WebSocket Upgrade.
- [ ] Проверить маршрут `/socket.io/` через домен PWA в production.
- [x] Открывать одно соединение для активного заказа. Регистрировать обработчики до подключения. После `connect` отправлять `order:subscribe` с `{ orderId, trackingToken }` и ждать `order:subscribed` до 5 секунд. Обрабатывать `order:statusChanged` и `exception`.
- [x] Брать токен из локальной записи и передавать его только в событии подписки и HTTP-заголовке `X-Tracking-Token`.
- [x] При смене заказа, уходе со страницы или получении `COMPLETED` либо `CANCELLED` закрывать соединение, отменять запросы и очищать таймеры.

## Версии и восстановление

- [x] Обрабатывать снимки `{ orderId, status, version }` из Socket.IO и `GET /orders/:id/status` одним обработчиком. Проверять ID, статус и положительную целую версию.
- [x] Принимать только более новую версию. Сохранять её со статусом в Pinia и `localStorage`. Для старых записей без версии использовать первый валидный снимок.
- [x] После подтверждения подписки сверять состояние по HTTP, чтобы получить изменения, произошедшие до входа в комнату. При скачке версии сразу отображать полученный статус и запускать сверку.
- [x] Выполнять не более одного GET одновременно. Если запрос начался до подтверждения подписки, запланировать одну дополнительную сверку. Проверять версию каждого запоздавшего ответа.

## Сбои и ограничения

- [x] При потере связи сохранять последний статус на экране и показывать «Восстанавливаем связь». Сразу сверяться по HTTP, затем повторять каждые 15 секунд. При ошибках увеличивать интервал до 60 секунд. После восстановления сокета и успешной сверки прекращать периодические запросы.
- [x] Управлять переподключением одним таймером с задержками 5, 10, 20, 40 и 60 секунд. Ограничить подписки шестью попытками за скользящую минуту на вкладку, включая переходы между заказами.
- [x] При `WS_ERROR` выдерживать 60 секунд до повторной подписки. При `BAD_REQUEST` остановить повторы для открытого заказа. При HTTP `401`, `403` или `404` остановить отслеживание и показать «Не удалось получить статус заказа».

## Проверка и выпуск

- [x] Запустить `npm run build --workspace=web`.
- [ ] В браузере проверить оформление, обновление без перезагрузки, сохранение статуса в истории и закрытие подписки после завершения заказа.
- [x] Проверить обрыв связи во время обновления, запоздавший HTTP-ответ, дубликат, скачок версии, чужой ID, ошибку подписки и быстрый переход между заказами. Подтвердить, что статус не откатывается и события предыдущего заказа не меняют состояние текущего заказа.
- [ ] Проверить WebSocket Upgrade в production и подписку из двух независимых клиентских сетей. Если прокси объединяет клиентов под одним адресом для лимита шлюза, согласовать исправление до выпуска.
